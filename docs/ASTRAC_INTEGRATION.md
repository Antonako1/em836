# AstraC Toolchain Integration — em836

This document describes how **em836** interfaces with the external **AstraC** assembler and compiler toolchain to automate the compilation and execution of x86 assembly and Astra C source files.

---

## 1. Architecture Overview

AstraC is an external x86 compiler and assembler targeting i386 architectures.
In `em836`, AstraC operates as a high-speed external builder:
- It transforms Assembly (`.as`, `.asm`) into executable `.bin` files via `AstraC.exe asm <input>`.
- It transforms Astra C (`.ac`) into executable `.bin` files via `AstraC.exe comp <input>`.
- All runtime emulation, instruction stepping, live disassembly, and visual rendering are handled completely within `em836` using Unicorn Engine, Capstone Engine, and SDL3.

```mermaid

    User[User / Editor / FileDrop] -->|Source Code| Toolchain[AstraCToolchain Controller]

```

---

## 2. Toolchain Discovery Hierarchy

When compilation is requested, `em836` resolves the path to `AstraC.exe` in the following strict order:

1. **User Custom Path**: Configured via **File -> Settings...** (persisted in `config.json`).
2. **Sibling Directory**: `../AstraC/build/Release/AstraC.exe` or `../../AstraC/build/Release/AstraC.exe`.
3. **Repository Directory**: `C:/Users/anton/source/repos/AstraC/build/Release/AstraC.exe`.
4. **Current Directory**: `./AstraC.exe` or `build/Release/AstraC.exe`.
5. **System PATH**: Searched via standard operating system lookup.

If AstraC is missing, `em836` displays a clear diagnostic in the **AstraC Build Log** directing the user to set the location in **File -> Settings...**.

---

## 3. Subprocess Execution & Output Capture

AstraC is invoked using the native Windows `CreateProcessA` API with an anonymous inherited pipe for `stdout` and `stderr`:
- Standard output and error streams are captured asynchronously into an in-memory buffer.
- Real-time build results, syntax warnings, symbol definitions, and error codes are routed to the **AstraC Build Log** tab.
- Subprocess timeout detection (10 seconds) prevents hangs if an external process fails to exit.

---

## 4. In-Memory / Buffer Compilation

When clicking **Compile & Run** in the embedded code editor:
1. `em836` serializes the editor text to a temporary source file in `%TEMP%/em836_buffer.as` (or `.ac`).
2. Spawns AstraC with the appropriate subcommand (`asm` or `comp`).
3. Captures compiler logs into the UI.
4. If compilation exits with code 0, `em836` pauses the CPU, clears existing memory, loads the binary payload, sets `EIP`, and begins execution immediately.

---

## 5. Binary Formats: Raw Flat Binary vs ACFH

### Raw Binary (`.BIN`)
- Standard format generated by AstraC raw assembly.
- Mapped starting at origin `0x00000000` (or configured base load address).
- `EIP` is initialized to the base address.

### ACFH Executable (`.EXE` / `type exe`)
AstraC executables start with a 112-byte packed header (`AcFileHeader`):

```c
#pragma pack(push, 1)
struct AcFileHeader {
    char magic[4];             // Must match "ACFH"
    uint16_t version_major;    // Major version
    uint16_t version_minor;    // Minor version
    uint32_t flags;            // Flags
    uint32_t entry_point;      // Execution entry point address
    uint32_t code_offset;      // File offset of code segment
    uint32_t code_size;        // Size in bytes of code segment
    uint32_t data_offset;      // File offset of data segment
    uint32_t data_size;        // Size in bytes of data segment
    uint32_t bss_size;         // Size in bytes of uninitialized BSS
    uint8_t reserved[76];      // Reserved padding (total: 112 bytes)
};
#pragma pack(pop)
```

`em836` parses this header automatically:
- Validates the magic string `ACFH`.
- Reads `entry_point` and loads the code segment (`code_offset`, `code_size`) into memory.
- Initializes `EIP = header.entry_point` automatically.
